④ 多模态输入 + Agent 能力感知
附件栏新增音频/视频入口，按钮角标实时反映当前模型的处理路径（原生 / 自动转写 / 抽帧绕行 / OCR）。系统提示词注入能力声明后，Agent 遇到不支持的模态会主动改用委派模型或 shell 工具绕行，而不是任务终止报错。

核心机制：从「静默剥离」到「告知 + 绕行」

为什么现在 Agent 会在任务中途报错终止，改造后如何避免

✗ HaoAI 现状 — 结构性静默门控
1. 用户发图/发任务Agent 按「有图」规划步骤（提示词里没有任何能力说明）
→
2. 请求构造层剥离vision=false → 图片被静默丢弃；tools=false → 工具列表清空。模型毫不知情
→
3. 中途断裂模型引用「刚才那张图」失败 / 虚拟屏截图链路 400 → 任务终止报错，用户困惑
✓ 改造后 — 能力解析器 + 提示词声明 + 委派工具
1. CapabilityResolver 统一解析用户覆盖 > models.dev 目录 > 名称启发式 → 得到 input/output 模态、tools、思考等级
→
2. 系统提示词注入能力声明「你能处理图像；不能处理视频/PDF——用 ffmpeg 抽帧 / OCR / delegate_to_vision 绕行，不要中断」
→
3. 模型自主绕行缺图像能力→调视觉委派模型；缺音频→ASR 转写；缺视频→抽帧。结构性门控保留为最后兜底，降级对模型可见
数据模型改造：ModelEntry 新增 inputModalities / outputModalities（text·image·audio·video·pdf）与 ModelOverrides 覆盖层（可"恢复自动检测"）；旧 vision/tools/reasoning 三态字段迁移映射，settingsVersion=2。
目录源切换：旧远端目录 → models.dev（内存→磁盘→内置 asset 三级缓存，离线可用），保留现有「检测能力」按钮语义。
新增内置工具：delegate_to_vision（视觉组代看）、transcribe_audio（ASR 代听），按「能力委派」区配置启用。
