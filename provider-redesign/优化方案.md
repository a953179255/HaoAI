# HaoAI 模型供应商优化方案

> 基于对 HaoAI 现有代码（`SettingsStore.kt` / `SettingsScreen.kt` / `AgentEngine.kt` / `SystemPrompt.kt` / `ModelCatalog.kt`）与同类成熟应用（模型数据模型/供应商配置/语音模态/目录 API 四模块）的完整源码分析。
> 效果图：`haoai-provider-redesign-mockup.html`（同目录）

---

## 一、现状诊断（HaoAI vs 成熟基准）

### 1.1 数据模型对比

| 维度 | HaoAI 现状 | 成熟基准 | 差距 |
|---|---|---|---|
| 能力字段 | `ModelEntry.vision/tools/reasoning` 三态布尔 | `inputModalities` + `outputModalities` 字符串列表（text/image/audio/video/pdf） | **HaoAI 无音频、无视频、无 PDF、无输出模态**；vision 一个布尔混管图像+视频 |
| 能力来源 | 旧版远端目录 + 模型名正则猜测 + 手动三态芯片，三套逻辑并存 | models.dev 目录（内存→磁盘→内置 asset 三级缓存）+ 名称启发式 + 用户 override，统一合并链 | HaoAI 目录源小众、无离线兜底 |
| 用户覆盖 | 直接改写 `ModelEntry`，无法"恢复自动检测" | `ModelOverrides` 独立一层，`isUserModified` 可感知、可重置 | HaoAI 覆盖后丢失自动更新能力 |
| 委派模型 | 无 | Vision Group（主模型不能看图→视觉模型代看）、Voice Input/Output Group（ASR/TTS 代听代说） | **核心差距**：不支持≠不能完成 |
| 思考等级 | reasoning 只有 true/false | `ThinkingLevel` 目录 + 每模型 effort tiers 白名单 + 用户上限 | HaoAI 无法精细控制 |

### 1.2 Agent 能力感知（用户反馈的核心痛点）

HaoAI 的门控是**纯结构性、静默的**：
- `AgentEngine.kt:1159`：`tools == false` → 请求不带 tools（模型不知道自己被剥夺了工具）
- `AgentEngine.kt:1480` + `buildApiMessages()`：不支持 vision → **静默丢弃图片**，仅在文本追加一行系统注记
- `SystemPrompt.kt`：**完全不描述模型能力**

后果：模型以为自己能看图/能调工具，按有图的前提规划任务；当任务链路依赖被剥离的能力（如虚拟屏截图识别）时，中途 400 或逻辑断裂 → **任务终止报错**，且模型不会自主绕行。

成熟基准的做法（capabilityPromptFragment 模式）：把能力**显式写进系统提示词**——
> "You can natively process images. You cannot natively process audio, video — for those formats, call shell_execute with ffmpeg or similar tools to extract text/metadata first."

模型知道边界 → 主动规避 → 改用替代路径完成任务。这正是用户要的"Agent 能知道该模型支持/不支持什么功能"。

### 1.3 多模态输入

- HaoAI 聊天仅支持图片附件（相册选图→base64→image_url）。**音频、视频输入完全缺失**。
- 成熟基准：音频走 ASR 模型转写（系统语音引擎或供应商 audio-in 模型），视频走 ffmpeg 抽帧/抽音轨后按能力路由。

### 1.4 UI 问题（用户明确吐槽）

- 每行供应商右侧同时放 **展开箭头 + 编辑 + 删除** 三个按钮，视觉噪音大、功能重复感强；
- 编辑塞在对话框里（`ProviderDialog` 300+ 行），字段一屏放不下，能力芯片藏在对话框底部；
- 列表上看不到模型能力（是否支持图像/音频/工具），要逐个展开才知道；
- 删除是危险操作却与编辑平级常驻，易误触。

## 二、优化方案

### P0 — 能力感知重构（解决"任务终止报错"）

**① 统一能力解析器 `CapabilityResolver`**（替代三套并存逻辑）

```
effectiveCaps(entry) =
    用户 override（ModelOverrides，最高优先级，带"已手动修改"标记）
 ?? models.dev 目录命中（inputModalities / outputModalities / reasoning / effort tiers / context）
 ?? 名称启发式（*-vl*→image, *-audio*/*asr*→audio, *video*→video, 兜底 text）
 ?? 保守默认（text-in / text-out）
```

- 目录源从 上游 切换为 **models.dev**（`https://models.dev/api.json`），并内置一份 `models-dev-api.json` asset 离线兜底（三级缓存：内存→磁盘→asset，照抄成熟架构）。
- `ModelEntry` 新增字段（向后兼容，默认 null）：`inputModalities: List<String>?`、`outputModalities: List<String>?`、`maxThinkingLevel`；旧 `vision` 字段迁移时映射为 `inputModalities ∋ image|video`。

**② 系统提示词注入能力片段 `capabilityPromptFragment()`**

`SystemPrompt.build()` 增加一段（仅当能力有缺口时注入）：

```
[模型能力声明] 当前模型 glm-5.3-flash 可直接处理：图像。
无法直接处理：音频、视频、PDF。
遇到无法直接处理的内容时，不要放弃任务：
- 优先使用可用工具绕行（如 OCR 工具、shell 抽帧转码）
- 若已配置委派模型，调用 delegate_to_vision / transcribe_audio 工具
- 向用户说明限制并给出替代方案，而不是中断
```

**③ 静默丢弃 → 显式告知 + 委派**

- 用户发图但主模型无 image-in：不再只追加一行小字，而是给 Agent 注入一条 system 消息"图像已附上但当前模型不可见，请使用 xxx 方式处理"；
- 新增两个内置工具（可选启用）：
  - `delegate_to_vision(imageRef)`：调用用户配置的**视觉委派模型**读图，把描述返回给主模型；
  - `transcribe_audio(fileRef)`：调用**语音模型**（供应商 audio-in 模型或系统 SpeechRecognizer）转写。
- 请求构造层门控保留（兜底防 400），但降级路径全部对模型可见。

### P0 — 输入模态补齐（音频/视频）

- 聊天附件栏新增 **录音/音频文件** 与 **视频** 入口；
- 主模型有 `audio`-in → 直发；无 → 自动走转写（系统 ASR 或委派模型），转写文本+原文件引用进消息；
- 视频：有 `video`-in 直发（供应商支持时）；否则 ffmpeg 抽关键帧当多图 + 抽音轨转写（HaoAI 已有 shell 工具基础）；
- 附件按钮按当前模型能力显示状态：支持=正常；不支持但可委派=带"自动转写/代看"角标；完全无路径=置灰+说明。

### P1 — 输出模态与思考等级

- `outputModalities` 设置（text/image/audio），驱动：纯生成类模型（如 TTS/文生图）不进 Agent 主循环候选列表（照抄成熟实现的 isTextOutput 过滤）；audio-out 模型可用于回复朗读。
- reasoning 升级为思考等级：目录提供 effort tiers 白名单（low/medium/high…），UI 下拉选择，请求构造层 clamp。

### P1 — UI 重构（去按钮化）

**列表页**：
- 行内只保留 **单选圆点 + 名称/模型 + 能力徽章 + 展开箭头**，编辑/删除按钮全部移除；
- 能力徽章直接外显（图/音/视/工具/推理 小芯片），一眼看清每个供应商能干什么；
- 展开行 = 模型清单（点=设默认）+ 行尾"编辑该供应商"文字链；
- 供应商的编辑/删除收进**详情页右上角 ⋯ 菜单**（编辑、复制、删除）+ 长按弹出菜单；删除仍需确认对话框。

**供应商详情页**（替代大对话框）：
- 分区卡片：连接（Base URL/Key/协议/测试）、默认模型、模型清单（搜索/添加/拉取列表/检测能力）、高级（采样参数、Key 池、余额）；
- 每个模型行显示模态徽章，点击进入**模型能力编辑页**。

**模型能力编辑页**（新页面，核心）：
- 输入模态：文本/图像/音频/视频/PDF 开关芯片组；
- 输出模态：文本/图像/音频；
- 能力：工具调用、思考（+等级下拉）、上下文窗口、最大输出；
- 顶部显示能力来源（自动检测自 models.dev / 名称推测 / 手动修改），一键"恢复自动检测"。

### P2 — 模型分组与路由（对齐成熟 ModelGroup 设计）

- 供应商内多模型可组"降级组"（fallback / loadBalance），已有 fallbackChain 雏形，升级为组概念；
- 视觉组 / 语音输入组 / 语音输出组的全局绑定入口（设置页"能力委派"区块）。

## 三、实施顺序与影响面

| 阶段 | 内容 | 涉及文件 | 风险 |
|---|---|---|---|
| S1 | CapabilityResolver + models.dev 目录 + ModelEntry 新字段（settingsVersion=2 迁移） | `SettingsStore.kt`、`ModelCatalog.kt`、新 `CapabilityResolver.kt` | 低（默认值兜底） |
| S2 | 系统提示词能力片段 + 降级路径显式化 | `SystemPrompt.kt`、`AgentEngine.kt` | 中（需回归 Agent 主流程） |
| S3 | 列表页去按钮化 + 供应商详情页 + 模型能力编辑页 | `SettingsScreen.kt`（拆分）、`SettingsViewModel.kt` | 低（纯 UI） |
| S4 | 音频/视频输入 + 转写/委派工具 | `ChatScreen.kt`、新 `DelegateTools.kt` | 中 |
| S5 | 输出模态、思考等级、模型分组 | 各层 | 低 |

验收标准（对照用户痛点）：
1. 选一个纯文本模型（如 glm-5.2 汤）发图 → Agent 不再中断，能说明限制或用 OCR/委派继续；
2. 列表页无任何行内编辑/删除按钮，视觉干净；
3. 供应商配置里可勾选音频/视频输入模态并即时生效；
4. 新供应商添加后点"检测能力"即可自动填好全部模态（models.dev 命中时）。
