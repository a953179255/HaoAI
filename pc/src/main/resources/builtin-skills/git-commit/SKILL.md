---
name: Git 提交规范
description: 要把改动提交进 git、需要写提交信息或决定怎么拆分提交时使用这个技能。
---
1. 先跑 `git status` 与 `git diff --staged`，看清到底改了什么，把无关文件剔出暂存区。
2. 按“一件事一个提交”分组：能独立回滚的改动才算一个提交，别把格式化与逻辑改动混在一起。
3. 写中文提交信息：首行不超过 50 字说清做了什么，空一行后补上改动原因与影响面。

产出格式：首行摘要 + 空行 + 要点列表（最多 3 条），末尾注明是否需要同步改文档或补测试。

常见坑：
- 提交前逐个确认新增文件，别把密钥、临时文件和构建产物一起带进去。
- 首行别只写“更新”“修复”这种没有信息量的词，回看历史时等于没写。
