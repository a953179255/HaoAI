---
name: 改动审阅
description: 手上有一份 git diff、补丁或变更清单，需要读懂它并判断能否应用与合入时使用。
---
1. 先看 `git diff --stat` 与涉及文件清单，估计改动范围，再逐块读正文。
2. 分清哪些是解决问题的必需改动，哪些是顺手的重排与格式化，后者单独标注出来。
3. 对每个改动块问三个问题：改对了吗、影响了谁、有没有漏掉配套改动，然后给出结论。

产出格式：第一行给结论（可合入 / 需修改 / 不建议），随后是改动要点与风险点各不超过 5 条，逐条标注文件与行号。

常见坑：
- 空白与换行重排会淹掉真正的改动，必要时用 `git diff -w` 忽略空白再看一遍。
- 只看 diff 不看被改函数的上下文会误判，尤其是参数语义或返回值变了的时候。
