---
name: 代码评审
description: 拿到一段新写的代码或一个 PR 需要评审、挑问题时使用这个技能。
---
1. 先读调用方与相关定义，弄清这段代码本来要做什么，再看它写成了什么样。
2. 按四条线过一遍：逻辑正确性与边界条件、并发与资源释放、安全与注入风险、可维护性与重复。
3. 有编译、测试或静态检查可跑就跑一遍，用结果佐证；跑不了的明确标成待验证。

产出格式：按“必须修复 / 建议改进 / 可选”三级列清单，每条带文件与行号、问题说明、修改建议；最后给一句总体结论。

常见坑：
- 只报有证据的问题，拿不准就写“待验证”，别凭印象编缺陷。
- 别纠缠与本次改动无关的旧代码风格，那会把评审变成批量重构。
