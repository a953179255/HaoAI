---
name: 发布说明
description: 版本即将发布，需要把这一版的改动整理成面向用户的 changelog 时使用。
---
1. 先圈范围：从上个版本标签比到当前提交，连同需求单一起核对，把改动列全。
2. 按“新增 / 修复 / 变更 / 破坏性变更”分组，用户无感的内部重构剔除或合并成一条。
3. 用用户视角改写每条：说清“现在能做什么了”，涉及行为变化的补上升级影响与迁移方式。

产出格式：`## 版本号（日期）` 标题 + 四个分组小节 + 每组要点列表，破坏性变更单独成节并放在最前。

常见坑：
- 别照抄提交信息，开发者语言用户读不懂，也不会去读。
- 版本号与日期要和发布单一致，别留占位符或写错上一版的日期。
